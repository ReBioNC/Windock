# Windock v0.1 (Phase 0 + Phase 1: Core Dock) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macOS-style dock for daily use on Windows 10: pins and running apps, magnification, blur, reserved screen space, a hidden taskbar with safe recovery, and a Settings window that applies changes immediately.

**Architecture:** Pure logic (settings, dock model, layout, animation, click decisions, taskbar coordination) lives in `Windock.Core` (net8.0, no WPF and no Win32) and is tested with xUnit. The WPF app `Windock` only holds windows, the renderer, and Win32 wrappers in `Interop/`, which implement interfaces from Core. Two spikes at the start validate the blur and taskbar hiding before production code is written.

**Tech Stack:** C# 12, .NET 8 (SDK 8.0.400), WPF, Microsoft.Windows.CsWin32, System.Text.Json, xUnit, GitHub Actions.

**Spec:** [docs/PRD.md](../../PRD.md), [docs/DESIGN.md](../../DESIGN.md), [docs/ARCHITECTURE.md](../../ARCHITECTURE.md)

**Outside this plan (Phase 2, separate plan):** F-07 (switching between windows), F-10 (bounce), F-11 (drag to reorder in the dock), S-01 left/right, S-07 dock auto-hide, S-08, S-09, and the "Start with Windows" prompt on first run. T-02 (taskbar auto-hide mode) is done in this plan, because it is only a few lines in `TaskbarModeCoordinator`.

## Global Constraints

- Core: `net8.0`. App: `net8.0-windows`. Tests: `net8.0`. `<Nullable>enable</Nullable>`, `<LangVersion>12</LangVersion>`, `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>` in every project.
- `Windock.Core` must not reference WPF, WinForms or Win32. `Windock` may reference Core, not the other way round.
- Win32 calls only in `src/Windock/Interop/`.
- `app.manifest`: `requestedExecutionLevel level="asInvoker"`, `dpiAwareness` `PerMonitorV2`, and `supportedOS` Windows 10.
- File writes only in `%AppData%\Windock\`. Registry: none in v0.1. The taskbar setting only through `ABM_SETSTATE`, recorded in `state.json` before it changes.
- No DLL injection, in-process hooks, `TerminateProcess`, or network access. Windows are only closed through `WM_CLOSE`.
- NuGet dependencies only: `Microsoft.Windows.CsWin32`, `xunit`, `xunit.runner.visualstudio`, `Microsoft.NET.Test.Sdk`.
- Code identifiers in English. User-facing UI text was in Indonesian at the time, following DESIGN.md (translated to English in v0.9).
- All sizes in DIP. Defaults and constants are taken exactly from DESIGN.md §2, §3, §4 and §6.
- Commits use Conventional Commits and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Push to `origin main` after every task.

## Review Focus

1. **Too many apps for the screen width:** the dock must not exceed the screen. Icons shrink evenly so the plate fits (tested in Task 6).
2. **`settings.json` edited by hand with one wrong value:** only that field falls back to its default, the rest stays (tested in Task 4).
3. **Windock killed while the taskbar is hidden:** the next time Windock starts, the taskbar and the original auto-hide setting are restored before anything else (tested in Task 8).
4. **Processes whose exe path cannot be read** (protected or Administrator processes): their windows still show, with an identity from the process name (tested in Task 7).
5. **Pins to apps that were uninstalled, or duplicate pins:** pins still show without crashing, and duplicates are merged into one icon (tested in Task 7).

Algorithm (coordinates relative to `DockWindow`, origin at the top left):

```
1. baseIcon = IconSize; ratio = MagnifiedSize / IconSize
   baseWidth = 2*PlatePaddingH + Σ(Icon: baseIcon+IconSpacing, Separator: SeparatorSlotWidth) × SlotProgress
   if baseWidth > ScreenWidth − 2*ScreenMargin:
       baseIcon = (ScreenWidth − 2*ScreenMargin − 2*PlatePaddingH − ΣSep×p − ΣIcon p×IconSpacing) / ΣIcon p
   magnified = baseIcon × ratio; R = ReachFactor × baseIcon
2. Each item's base center comes from the layout without magnification, centered on ScreenWidth/2
3. For Icon: d = CursorX − baseCenter (if CursorX is null or magnification is off, scale = 1)
   t = min(|d|/R, 1); s = 1 + (magnified/baseIcon − 1) × cos²(t·π/2)
   s = 1 + (s − 1) × MagnifyProgress; size = baseIcon × s
   slotWidth = (size + IconSpacing) × SlotProgress
4. Plate: width = 2*PlatePaddingH + Σ slotWidth; X = (ScreenWidth − width)/2
   height = PlateHeight(baseIcon); Y = WindowHeight − EdgeGap − height
5. Icons are anchored at the bottom: bottom = Plate.Bottom − PlatePaddingV − IndicatorSpace; centered in the slot
   Indicator: CenterX = Bounds.CenterX; CenterY = Bounds.Bottom + IndicatorOffset + IndicatorDiameter/2
   Separator: Bounds width 1, height 0.6×baseIcon, CenterY equal to the base icon center, centered in the slot
6. ActiveZone: if CursorX != null or MagnifyProgress > 0, then X = Plate.X, width = Plate.Width,
   Y = min(Plate.Y, min icon Bounds.Y), bottom = WindowHeight. Otherwise, the Plate from Plate.Y to WindowHeight.
```
