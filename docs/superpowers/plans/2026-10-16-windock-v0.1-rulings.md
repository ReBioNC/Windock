Dicatat saat menjalankan [rencana v0.1](2026-10-16-windock-v0.1-dock-core.md). Format: keputusan — alasan — risikonya kalau keliru.

## Keputusan (ruling)

- Setup: Ruling: work directly on main and push after each task — user approved plan whose Global Constraints say "push ke origin main setelah setiap task", and user granted repo management (commit + push) — cost if wrong: history on main instead of a branch; reversible via revert.
- Setup: Ruling: user said "kamu boleh testing tapi hasil akhirnya biar aku yang jalankan" — I run spikes/manual verifications myself (always restoring taskbar), final hands-on run is the user's — cost if wrong: steps flagged "bersama pengguna" verified by me only.
- Task 1: Ruling: backdrop must be a raw Win32 popup resized to the plate each frame (not a fixed-size WPF window with a region) — DWM blur ignores region on a fixed-size window and resizing a WPF window per frame costs up to 245 ms/frame — cost if wrong: small rework of BackdropWindow in Task 13.
- Task 1: Ruling: Acrylic not offered in v0.1 settings; stored "Acrylic" treated as Standard — acrylic ignores window region (square corners) — cost if wrong: one option missing; DESIGN §6/ARCH §4 to be updated at checkpoint.
- Task 1: Ruling: DPI 125% check deferred to user's final run — changing display scale is a system setting I must not modify — cost if wrong: DPI bug found later by user.
- Task 2: Ruling: hide taskbar ~700 ms after ABM_SETSTATE and keep it hidden (re-hide when shown unless foreground is Start/Search/taskbar) — immediate SW_HIDE is undone by the autohide transition, leaving a 2 px peek strip that pops the taskbar over the dock — cost if wrong: brief taskbar flash at startup.
- Task 2: Ruling: Explorer-restart (TaskbarCreated) check deferred to user's final run — restarting Explorer would close the user's open Explorer windows — cost if wrong: re-apply bug found later.
- Checkpoint: Ruling: ARCHITECTURE §4/§7.2, DESIGN §6, PRD S-04 and plan Tasks 13/15/16/17 updated with spike results (commit "docs: update architecture from spike results") — spec must match what was proven — cost if wrong: none beyond doc churn.
- Task 3: Ruling: DockSettings overrides Equals/GetHashCode to compare Pins by content — record equality on IReadOnlyList compares references, which would break roundtrip/no-change tests in Task 4 — cost if wrong: none.
- Task 3: Ruling: NoWarn WFAC010 in Windock.csproj — WinForms analyzer (pulled in for NotifyIcon) rejects manifest DPI settings that WPF requires — cost if wrong: none.
- Task 3: Ruling: dropped template's coverlet.collector package — Global Constraints allow only CsWin32/xunit/runner/Test.Sdk — cost if wrong: no coverage collection.
- Task 4: Ruling: corrupt settings.json is moved (not copied) to settings.corrupt-*.json — keeps the good .bak from being overwritten by the next save — cost if wrong: none.
- Task 7: Ruling: plan test "Removed == [C]" corrected to ["sep:pinned", C] — the pinned separator correctly disappears with the last unpinned app — cost if wrong: none.
- Task 7: Ruling: ClickAction cases are nested records (ClickAction.Launch, .Activate, .Minimize, .OpenRecycleBin.Instance, .None.Instance) — avoids top-level names clashing with WPF/Win32 identifiers — cost if wrong: rename only.
- Task 7: Ruling: DockItem overrides Equals to compare Windows by content and exposes key constants (PinnedSeparatorKey, TrashSeparatorKey, RecycleBinKey) — needed for diffing — cost if wrong: none.
- Task 8: Ruling: switching Hidden→AutoHide calls ShowTaskbarWindows (plan only said keep original state) — otherwise the taskbar would stay SW_HIDE in AutoHide mode — cost if wrong: none.
- Task 10: Ruling: hand-written P/Invoke in src/Windock/Interop/Native.cs instead of CsWin32 — signatures already proven in spikes; CsWin32's generated HWND/SafeHandle wrappers add friction for no safety gain here — cost if wrong: manual signature bugs (mitigated: each used in manual verification).
- Task 11: Ruling: window AppId uses AUMID only for packaged apps (exe under \WindowsApps\), otherwise exe path; .lnk pins resolve to target exe (Squirrel Update.exe --processStart resolved to newest app-*\X.exe), AUMID only when the shortcut has no target — observed: Chrome windows carry AUMID "Chrome" while exe pins have none, so AUMID-first (ARCH §6.2) would split pinned/running icons — cost if wrong: Store apps pinned via .lnk may not merge with their window.
- Task 11: Ruling: added re-entrancy guard (TryAdd after Describe) — COM calls in Describe pump messages and re-entered the hook, adding Notepad twice (seen in manual test) — cost if wrong: none.
- Task 11: Ruling: WindowTracker exposes RawEvent(evt, hwnd) for the taskbar keep-hidden logic (Task 16) instead of a TaskbarShown event — one hook set serves both — cost if wrong: none.
- Task 12: Ruling: icon order is window icon (no path) → package manifest unplated logo (AppxManifest.xml near the exe) → shell image (aumid via shell:AppsFolder, else path) → generic — shell images of Store apps come on a coloured tile, which looks wrong in a mac-style dock — cost if wrong: an app with a manifest gets its manifest logo instead of the exe icon.
- Task 12: Ruling: packaged processes without a window AUMID use GetApplicationUserModelId(process) — WhatsApp/Claude windows have no window AUMID — cost if wrong: none.
- Task 13: Ruling: DockWindow is a code-only Window (no .xaml) and DarkTheme.xaml moves to Task 14 where menus need it — the window has no markup worth a XAML file — cost if wrong: none.
- Task 13: Ruling: "pinned" separator only when at least one pin exists (new test No_leading_separator_when_nothing_is_pinned) — the first manual run showed a separator at the dock's left edge with no pins — cost if wrong: none.
- Task 13: Ruling: pressed icon uses 70% opacity instead of 70% brightness — WPF brightness needs a shader effect per icon; on the dark plate the result looks the same — cost if wrong: slightly different press look.
- Task 13: Ruling: render loop also detaches while the pointer rests without moving (dirty flag) — plan kept it hooked while the pointer is inside; static frames need no work — cost if wrong: none.
- Task 14: Ruling: running Store apps are pinned as "shell:AppsFolder\<AUMID>" and PinResolver/AppLauncher understand that form — their exe in WindowsApps cannot be launched directly and has a different AppId than the window — cost if wrong: Store pins need re-pinning if the format changes.
- Task 14: Ruling: plate menu omits "Kunci posisi pin" (Phase 2) and Recycle Bin gets a one-item "Buka" menu — DESIGN §5 lists no Recycle Bin menu; plate fallback would be confusing — cost if wrong: none.
- Task 15: Ruling: AppBarService reports the reserved strip's bottom edge and the dock window sits on it — with the taskbar visible (mode "Biarkan tampil") QUERYPOS places the strip above the taskbar and the dock must follow — cost if wrong: none.
- Task 15: Ruling: display-change handling listens to WM_DISPLAYCHANGE/WM_DPICHANGED only, not WM_SETTINGCHANGE — our own SETPOS broadcasts work-area SETTINGCHANGE, which would cause churn — cost if wrong: a work-area change by another app bar may not re-seat the dock until the next POSCHANGED.
- Task 16: Ruling: keep-hidden exempts only Start/Search (Windows.UI.Core.CoreWindow) in front, and re-checks 1 s and 3 s after the delayed hide — after a crash recovery the back-to-back auto-hide flip re-showed the taskbar late; with the re-checks it is hidden again within ~3–6 s — cost if wrong: taskbar briefly visible after a recovery start.
- Task 16: Ruling: verified by probe — hide, Start open/close, emergency hotkey exit, hard kill + restart recovery, Keluar. Not verified here: Explorer restart (TaskbarCreated), sleep/resume, tray Pause/Lanjutkan (WinForms tray menu not automatable here) — left for the user's final run — cost if wrong: those paths may misbehave until reported.
- Task 17: Ruling: blur and taskbar mode use radio buttons instead of ComboBoxes — WPF's default ComboBox is light-themed and a dark template is large; 2–3 options read fine as radios — cost if wrong: cosmetic.
- Task 17: Ruling: settings styles live in App resources (SettingsTheme.xaml) — keyed StaticResources in UserControl pages must resolve at load time — cost if wrong: none.
- Task 17: Ruling: the "shortcut darurat" hint shows whenever "Sembunyikan total" is selected, not only the first time — simpler and always useful — cost if wrong: none.
- Task 17: Ruling: emergency hotkey is unregistered while the recorder box has focus — found in testing: recording the current hotkey quit Windock — cost if wrong: none.
- Task 17: Ruling: added session.lock marker; on start after an unclean exit (and no taskbar recovery), flip auto-hide off/on once to make the shell drop the dead app bar's reserved space — found in testing: a hard kill in "Biarkan tampil" mode left 70 px reserved; same-state ABM_SETSTATE, ABM_NEW/REMOVE did not clear it, a flip did — cost if wrong: one brief taskbar flicker after a crash.
- Task 18: Ruling: tag v0.1.0 is created after the final review and its fixes, not in Task 18 — tagging before the review would point the tag at unreviewed code — cost if wrong: none.
